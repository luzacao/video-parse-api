# 小红书图文笔记与实况图的 image_list 字段怎么用（2026-08-23）

今天要解决的问题很具体：当你用短视频去水印 API 解析小红书分享链接时，返回结果里的 `image_list` 到底长什么样、怎么取图、实况图（Live Photo）又该怎么拿。很多开发者第一次对接小红书图文笔记，看到 `image_list` 是数组就以为全是字符串，结果一取就报错——因为小红书图文笔记的 `image_list` 元素可能是对象，里面还藏着 `live_photo_url`。

## 先搞清楚 image_list 的两种形态

以 `POST /api/parse` 接口为准，`data.image_list` 是一个数组，元素有两种可能：

**纯字符串**：直接是图片地址，多见于普通图集。

```json
"image_list": [
  "https://example.com/img/1.jpg",
  "https://example.com/img/2.jpg"
]
```

**对象结构**：小红书图文笔记、实况图笔记会返回这种，每个元素包含 `url` 和可选的 `live_photo_url`。

```json
"image_list": [
  {
    "url": "https://example.com/img/1.jpg",
    "live_photo_url": "https://example.com/live/1.mov"
  },
  {
    "url": "https://example.com/img/2.jpg"
  }
]
```

注意：只有小红书实况图笔记才可能有 `live_photo_url`，普通图文笔记的 `image_list` 元素即使走对象结构，`live_photo_url` 也可能为空。所以处理时一定要先判断类型，再决定怎么取值。

## 对接步骤：Python 示例

用 Python 写一个兼容两种形态的解析逻辑，直接复制就能跑：

```python
import requests

def parse_xhs(share_text: str, api_key: str):
    r = requests.post(
        "https://video.zacao.top/api/parse",
        headers={"X-API-Key": api_key},
        json={"text": share_text},
        timeout=30,
    )
    data = r.json()
    if data.get("code") != 200:
        print("解析失败:", data.get("message"))
        return None

    item = data["data"]
    print("平台:", item.get("platform"))
    print("标题:", item.get("title"))

    image_list = item.get("image_list") or []
    for idx, img in enumerate(image_list, 1):
        if isinstance(img, str):
            # 纯字符串，直接是图片地址
            print(f"图{idx}: {img}")
        elif isinstance(img, dict):
            # 对象结构，取 url 和实况图
            print(f"图{idx}: {img.get('url')}")
            if img.get("live_photo_url"):
                print(f"  实况图: {img.get('live_photo_url')}")

    return item

# 使用示例，Key 在 https://video.zacao.top/buy 购买
parse_xhs("复制的小红书分享链接", "mp_你的key")
```

如果你用的是 `GET|POST /api/parse/v2`，兼容字段里还有 `imgUrls`（图集 URL 列表）和 `sourceImgUrls`，但这两个是纯字符串数组，不含实况图。要拿实况图，还是得用 `/api/parse` 的 `image_list`。

## 常见坑

1. **别把 `image_list` 当纯字符串数组**。小红书图文笔记返回对象结构的概率很高，直接遍历取字符串会报 `TypeError` 或拿到 `None`。

2. **实况图是 `.mov` 或视频地址**。`live_photo_url` 是一段短视频，不是图片，前端展示时注意区分，别直接塞进 `<img>` 标签。

3. **直链有时效**。解析成功后尽快转存到自己的存储或 CDN，不要把 `url` 或 `live_photo_url` 当永久地址缓存，过几小时可能就 403 了。

4. **小红书短链有时需要完整口令**。只传 `xhslink.com` 的短链有时会解析失败，让用户从 App 里点「复制链接」拿完整分享文案再传。

5. **图文笔记也可能返回 `video_url` 为空**。如果 `image_list` 为空且没有 `video_url`，检查一下是不是链接传错或作品已删除（返回 404）。
