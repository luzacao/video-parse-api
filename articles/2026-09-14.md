## 先弄明白 image_list 长什么样

别的接口返回个 `video_url` 就完事了，图文笔记不行，它是一组图。所以 `data.image_list` 被设计成一个数组，元素有两种形态：

- **纯字符串**：普通图文，元素就是图片直链。
- **对象**：笔记里混着实况图时，元素是 `{ "url", "live_photo_url" }`，`url` 是静态封面，`live_photo_url` 才是那段会动的实况视频。

一段分享文案丢进去，接口会自己判断这是视频还是图文，不用你额外传 `platform` 或 `type`。想显式区分，用 `GET|POST /api/parse/v2`，它的 `type` 字段 `1` 是视频、`0` 是图文，另外还给一份扁平的 `imgUrls` / `sourceImgUrls` 列表，方便旧客户端直接对接。

## 一次调用，把六张图拆出来

请求还是老样子，Base URL 是 `https://video.zacao.top`，走 `POST /api/parse`，Header 带 `X-API-Key`：

```bash
curl -X POST 'https://video.zacao.top/api/parse' \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: mp_xxxx' \
  -d '{"text":"这条小红书笔记的完整分享口令……"}'
```

拿回 `image_list` 之后，Python 里遍历一遍就好。关键在于**判断元素类型**，别一刀切：

```python
import requests

r = requests.post(
    "https://video.zacao.top/api/parse",
    headers={"X-API-Key": "mp_xxxx"},
    json={"text": "小红书分享口令"},
    timeout=30,
)
data = r.json()["data"]

for item in data.get("image_list", []):
    if isinstance(item, dict):
        print("静态图：", item["url"])
        live = item.get("live_photo_url")
        if live:
            print("实况视频：", live)
    else:
        print("静态图：", item)
```

这里有个小坑：实况图的 `live_photo_url` 是视频流，别当成图片塞进 `<img>` 标签，用 `<video>` 或者直接下载落盘。另外所有直链都有时效，解析成功就尽快转存，不要缓存 `source_video_url` 当永久地址——这条同样适用于 `image_list` 里的 URL。

## 想连着点赞收藏一起抓？

如果你做的是数据分析，光要图不够，还想知道这条笔记的数据表现，那就换 `GET|POST /api/detail`。它目前覆盖 **抖音、小红书、视频号**，返回标题、发布时间、作者，以及 `stats` 里的点赞 / 评论 / 收藏 / 分享 / 播放。注意它**只给详情，不给图片视频直链**，所以图集还是得走 `/api/parse`。
