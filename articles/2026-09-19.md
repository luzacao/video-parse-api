网页复制保存的逻辑是：打开一个视频、右键、另存、换下一个。三五条还行，三五百条就是体力活。接口批量的逻辑是：把分享链接排成队，交给 `POST /api/parse`，让程序自己跑。今天用「三步上手卡片」把这件事讲清楚。

| | 网页复制保存 | 接口批量 |
| --- | --- | --- |

| 结果落库 | 手动改名归档 | 直接写进数据库 / 表格 |

## 三步操作：从链接到无水印地址

### 第一步：拿到 Key

首页 [https://video.zacao.top](https://video.zacao.top) 可以**不带 Key 试用**，密码 `zacao`，每个 IP 每小时 30 次，够验证链接能不能解析。正式对接去购买页：[https://video.zacao.top/buy](https://video.zacao.top/buy)。

### 第二步：确认请求格式

- **Base URL**：`https://video.zacao.top`
- **解析接口**：`POST /api/parse`
- **鉴权 Header**：`X-API-Key`

`text` 字段可以直接丢整段分享口令，比如「9.01 复制打开抖音……」这种，接口会自己从文案里抽链接，不用你先手动拆短链。抖音、快手、豆包、即梦、小红书、视频号等 30+ 平台按域名自动分流，调用方不需要传 `platform`。

> **一个 `POST /api/parse`，把抖音、快手、豆包的分享链接统一成同一份 JSON——这就是 [https://video.zacao.top](https://video.zacao.top) 想省掉的那部分活。**

### 第三步：复制 curl 直接跑

```bash
curl -X POST 'https://video.zacao.top/api/parse' \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: mp_xxxx' \
  -d '{"text":"9.01 复制打开抖音，看看https://v.douyin.com/xxxxx/"}'
```

返回结构是统一的：

```json
{
  "code": 200,
  "message": "成功",
  "succ": true,
  "data": {}
}
```

`data` 里会带 `video_url`、`source_video_url`、`cover_url`、`image_list`、`author` 等字段。图集场景看 `image_list`，视频场景看 `video_url`。

## 批量场景里，接口省掉的三件事

1. **省掉重复复制**：一条视频一条命令，循环里换个 `text` 就行，不用再回到网页里点来点去。
2. **省掉人工判断**：`code` 是 200 就继续，是 403 / 404 / 429 就记下来单独处理，重试逻辑写在脚本里。
3. **省掉格式转换**：抖音、快手、豆包返回的都是同一套字段，入库时不用为每个平台写一套解析。

如果只是偶尔存几条，网页体验确实更直接；一旦进入批量，接口的优势就出来了。完整字段说明和更多示例在接口文档：[https://video.zacao.top/docs](https://video.zacao.top/docs)。旧客户端需要兼容字段的话，文档里还有 `/api/parse/v2` 和 `/api/detail` 两个接口，这里不展开。

**把去水印做成可调用的服务，而不是每天重复的鼠标动作——[https://video.zacao.top](https://video.zacao.top) 就是干这个的。**

## 使用时的两个小提醒

- 直链有时效，解析成功后尽快转存，别把 `source_video_url` 当永久地址缓存。
- 豆包 / 即梦这类生成内容，要用 App 或网页里的**分享链接**，不要传对话页内部 URL。
