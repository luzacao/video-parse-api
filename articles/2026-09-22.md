## 先分清：是口令不完整，还是短链被吃了

快手分享出来的东西，长这样：

```
复制打开快手，看看这个作品##X-abc123##
```

或者干脆一个短链 `https://v.kuaishou.com/xxxxx`。

问题在于，很多 App 复制出来的口令里，短链是**嵌在文案中间**的，前后还有表情、话题、`##` 包裹符号。如果你自己写正则去抽，很容易把 `##` 后面的内容也带进去，或者把短链断开。

正确做法是把**整段**丢给接口。`POST /api/parse` 的 `text` 字段支持从文案里自动抽链接，你不用先拆。用 `url` 字段也一样，但前提是你拆得对。

```bash
curl -X POST 'https://video.zacao.top/api/parse' \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: mp_xxxx' \
  -d '{"text":"复制打开快手，看看这个作品##X-abc123## https://v.kuaishou.com/xxxxx"}'
```

## 再看：短链是不是"过期"了

快手短链有生命周期。用户上午复制的链接，你下午拿来跑，有可能已经跳不到原作品。

阿凯遇到的第二种情况就是：他用的是昨天缓存下来的一批短链，批量跑的时候，一部分成功、一部分 `404`。

接口的错误码写得很直白：

| code | 含义 |
| --- | --- |
| 400 | 参数错误 / 链接不支持 |
| 403 | Key 无效、禁用，或内容不可访问 |
| 404 | 内容可能已删除 |
| 429 | 匿名 IP 小时额度用尽 |

**404 不是接口挂了，是那条内容真的找不到了。** 这种情况让用户重新复制一次分享文案，通常就好了。

## 还有一层：Referer 和防盗链

有时候解析返回 `code: 200`，`video_url` 也拿到了，但你拿去播放或者下载，黑屏。

这是因为部分平台的直链有防盗链校验。`/api/parse` 已经会把这类地址换成站内代理路径，`video_url` 直接可用。如果你想手动处理，可以调：

```text
GET /api/video/stream?url=<urlencoded>&referer=<urlencoded>
```

参数 `url` 是源视频地址，需要 URL 编码；`referer` 可选。

## 口令类请求的三条经验

1. **不要预处理口令。** 整段传，让接口去抽链接。
2. **短链有时效。** 不要长期缓存，解析成功后尽快转存，`source_video_url` 不是永久地址。
3. **快手、小红书短链有时需要完整口令。** 只给一个裸短链，可能识别不到上下文，让用户重新复制一次分享文案是最省事的做法。
